# 分层实现路径

> 方案体系按「成熟度×依赖关系」分为四层。每一层以上一层的闭环验证为前提条件，不预设刚性时间表。层级之间不是「什么时候做」，而是「做到什么程度才能往下一层走」。

---

## 总览

```
基础层（现在可做）→ 核心层（基础验证后）→ 扩展层（核心稳定后）→ 全态层（条件成熟后）

      封闭沙盒              区域验证               半开放众包              全民众包
      可控、可审计          跨区域、多主体          有限开放、规模化          全民参与、标准化
```

---

## 第一层：基础层（封闭沙盒验证期）

### 核心命题

在绿电园区内跑通「数据从原始非结构化文档到结构化数据产品」的最小闭环。验证数据价值链的物理可行性。

### 实现条件

- 绿电园区物理基础设施已就位（算力、电力、数据存储）
- 园区内有可培训的本地劳动力
- 有至少一个真实数据源合作方（如地方档案馆、医院、国企）

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **物理底座** | 绿电园区运行、算力池上线 | 对应专报一/二 |
| **数据源接入** | 1-2个数据源方签署合作协议 | 政务档案或国企图纸 |
| **数据结构化** | OCR/NLP基础管线部署 | 可AI辅助，人工审核 |
| **数据标注** | 园区劳动力完成初级标注任务 | 标准化的通用任务 |
| **贡献值记录** | **仅轨道A（基础贡献值）** | 工时×准确率，先不做事后修正 |
| **存证** | 核心操作上链存证（血缘+贡献值） | 可用轻量联盟链 |
| **分配** | 预分配机制（虚拟代币或人工审核后发放） | 不跑智能合约自动分润 |

### 本层不做的

- 不做市场检验修正（轨道B）——下游还没有真实AI产品产生利润
- 不做智能合约自动分润——收益流还没有形成
- 不做消费者池——数据产品还没有终端用户
- 不做税收嵌入——分配规模太小，暂按现有税制处理
- 不做跨省SPV税收分享——本层只在单一园区内

### 本层产出

- 至少一个完整的数据产品闭环案例（如某档案馆的历史文档数字化后成为可查询数据集）
- 贡献值记录系统的基础数据积累（足够校准轨道A的参数）
- 标注员真实收入数据（对照基础贡献值，为下一层做基准）

### 达标验收标准

- 至少完成两类数据源的处理（如政务档案+工业图纸）
- 贡献值记录的完整性 > 98%
- 参与者对分配公平性的主观满意度 > 60%

---

## 第二层：核心层（区域验证期）

### 核心命题

在基础层验证通过后，引入真实的市场化收益流，启用智能合约自动分润和轨道B市场修正。从「模拟分配」切换到「真实分配」。

### 实现条件

- 基础层达标验收通过
- 有至少一个东部城市的数据源与园区数据链路打通
- 有一个或多个AI产品开发者愿意基于园区数据元件开发真实产品
- 联盟链基础设施完成部署

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **跨区域数据对接** | 1-2个东部城市的政务/企业数据源接入 | 测试跨区域隐私保护 |
| **数据元件化** | 将结构化数据封装为标准数据元件 | 标准化接口、元数据规范 |
| **数据产品开发** | 外部开发者基于数据元件开发真实AI产品 | 产品在市场中产生真实利润 |
| **贡献值计量** | **轨道A + 轨道B（市场检验修正）** | 双轨制正式运行 |
| **智能合约分润** | 利润沿数据价值链自动分配 | 合约部署在联盟链上 |
| **SPV法人治理** | 园区SPV正式运营，管理利润流和分配流 | 独立审计 |
| **数字人民币结算** | 分配款以数字人民币到账 | 参与者开立数字钱包 |
| **基础治理** | 试点社区投票确定参数初始值 | 复杂度等级映射等 |

### 本层不做的

- 不做半开放众包——加工方限于园区培训的本地劳动力和远程审核员
- 不做消费者池——终端产品利润先全部分配给生产者
- 不做历史贡献因子——先在核心机制跑通后再扩展
- 不做合成数据衰减——本阶段合成数据占比低

### 本层产出

- 智能合约自动分润在真实环境中连续运行超过6个月
- 轨道B（市场修正）的设计参数经真实数据校准
- SPV治理结构、成本核算、分润频率经过独立审计

### 达标验收标准

- 智能合约分润触发次数 > 100次，无合约执行错误
- 参与者分润到账的满意率 > 70%
- 数据产品至少产生可统计的市场收益
- 跨区域数据传输的安全审计通过

---

## 第三层：扩展层（半开放众包期）

### 核心命题

在核心机制稳定运行后，将参与范围从「园区内部+少量外部」扩展为「特定区域+特定技能人群」。同时引入AI工具增益归算、历史贡献因子、税收三层嵌入。

### 实现条件

- 核心层稳定运行超过12个月
- 贡献值标准化在试点社区达成共识
- 监管机构确认方案符合现有法规框架
- 数字人民币智能合约接口可用

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **半开放众包** | 向特定区域/技能人群开放初级标注任务 | 先培训后上岗，准入管理 |
| **分布式数据源** | 多方数据源持续接入 | 政府+企业+科研机构 |
| **AI工具增益归算** | 产出量加成系数正式运行 | 效率增益归操作者 |
| **历史贡献因子** | 5%-10%归出生地政府的机制上线 | 需实际居住年限条件 |
| **税收三层嵌入** | 个人所得税归工作地 / 企业税跨省分享 / 出生地回偿 | 税务机关监管节点接入联盟链 |
| **跨省SPV税收分享** | 东西部省份按约定比例分享企业利润税 | SPV合作协议固化 |
| **治理双层设计** | 社区治理层+公共治理层分治 | 投票机制进入运行 |
| **熔断机制** | 三方多签熔断部署 | 受独立审计 |

### 本层不做的

- 不做全民众包——仅限于经过培训认证的参与者
- 不做消费者池——本层仍以生产者为核心
- 不做合成数据代际衰减——合成数据占比尚未达到需要规则的程度

### 本层产出

- 跨区域、多主体的分布式数据价值网络初步形成
- 历史贡献因子运行数据——验证对出生地政府的实际激励效果
- 税收三层嵌入在税务机关审计中通过

### 达标验收标准

- 外部参与者的贡献值满意度 > 70%
- 历史贡献因子给出生地政府带来的实际回流金额有统计数据
- 至少两个出生地政府基于回流数据调整了教育/人口投入策略
- 半开放众包的质量控制体系通过独立审计

---

## 第四层：全态层（全民众包期）

### 核心命题

整个系统的最终形态。生产者池+消费者池双向分润、合成数据代际衰减、跨平台数据协议标准化。从「行业分配机制」进化为「社会级参与范式」。

### 实现条件

前三层全部达标。且：

- 贡献值量化标准已被至少一个国家级标准组织采纳
- 智能合约分润机制已在真实环境中连续运行超过12个月无重大争议
- 数据隐私保护和监管机制已通过独立合规审计
- 平台已具备处理多源异构数据的大规模并发能力

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **全民众包** | 全类型任务向社会开放，无需培训认证即可参与初级任务 | 质量校验层把关 |
| **消费者池** | 终端利润的10%-15%分配给消费者 | 先覆盖可验证链上消费 |
| **双向分润** | 生产者池+消费者池并行运行 | 两条独立轨道 |
| **消费值计量** | 初期用链上消费记录做代理变量 | 传播类/注意力类暂不纳入 |
| **合成数据代际衰减** | 等比衰减规则正式运行 | 合成数据占比已需要规则 |
| **跨平台数据协议** | 推动数据贡献追踪协议的行业标准 | 中长期标准化工作 |
| **开发者反垄断** | 公共数据元件强制开放条款生效 | 防止数据垄断 |
| **全面治理成熟** | 全部参数实现链上治理，消费者纳入投票体系 | |

### 本层产出

- 亿级参与者覆盖的全民数据价值生态
- 消费者分润的宏观数据（验证对消费行为的激励效果）
- 合成数据衰减规则在真实场景中的运行数据
- 跨平台数据贡献协议的标准草案

---

## 层级递进逻辑

```
基础层：     验证「数据能不能变成产品」
              ↓
核心层：     验证「产品利润能不能自动分润」
              ↓
扩展层：     验证「更多人和更多区域能不能参与进来」
              ↓
全态层：     验证「全社会的生产者和消费者能不能一起分享」
```

---

## 每层可以失败

失败是预期的。每层失败的结果不是退回方案本身，而是让方案产生一个明确的修订版。

| 层级 | 最可能的失败点 | 失败后的修正方向 |
|------|-------------|----------------|
| 基础层 | 贡献值记录的数据质量不足以支撑后续计算 | 重新设计「何为一个有效的贡献记录单元」 |
| 核心层 | 轨道B修正因子与实际市场价值偏差过大 | 切换工程近似方法或调整α值 |
| 扩展层 | 历史贡献因子未产生预期的出生地激励 | 调整比例或生效条件 |
| 全态层 | 消费者分润被套利 | 收紧消费值计量口径 |

每层失败都有明确的诊断方向和修正空间。方案不承诺一步成功，承诺的是每一次迭代都比上一次接近正确。

---

## 与四阶段演进路径的对应关系

本分层设计对应方案已有演进路径，但每一层的模块划分更精细：

| 演进阶段 | 对应层级 | 核心交付 |
|---------|---------|---------|
| 阶段一：封闭验证 | 基础层 | 数据价值链的物理可行性 |
| 阶段二：区域验证 | 核心层 | 智能合约分润的工程可行性 |
| 阶段三：半开放众包 | 扩展层 | 多主体、跨区域的制度可行性 |
| 阶段四：全民众包 | 全态层 | 全民参与的社会可行性 |
