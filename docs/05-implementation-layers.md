# 分层实现路径

> 方案体系按「成熟度×依赖关系」分为四层。每一层以上一层的闭环验证为前提条件，不预设刚性时间表。层级之间不是「什么时候做」，而是「做到什么程度才能往下一层走」。

---

## 场景推进策略（从易到难）

方案落地的数据来源遵循「先公共、后企业、再全民」的次序。这不是拍脑袋，是由制度基础决定的：

| | 公共数据 | 企业数据（联邦） | 全社会数据 |
|---|---|---|---|
| 权属争议 | 清晰（全民所有，国家代持） | 模糊（企业 vs 数据来源方） | 复杂 |
| 合规成本 | 低（脱敏后即可共享） | 高（商业秘密、隐私、合规） | 最高 |
| 开放意愿 | 政策驱动，有考核指标 | 利益驱动，有竞争顾虑 | 零散 |
| 数据质量 | 相对规范 | 参差不齐 | 不可控 |

### 第一步：公共数据池（0-2年）

**场景**：政府公开数据 + 国企行业数据（医疗档案、交通路网、司法文书、气象水文）

**为什么先走这一步**：
- 国家数据局已在推"公共数据跑起来"，政策窗口已经打开
- 数据权属清晰——全民所有，国家代持，不存在"这是谁的数据"的争议
- 脱敏后即可使用，不需要跟任何企业谈判
- 政府自身就是数据产品的第一买家（智慧城市、数字政务、公共卫生）

**目标**：跑通完整闭环，校准贡献值参数。

### 第二步：行业联邦节点（2-4年）

**场景**：大型企业和机构通过隐私计算接入联邦网络，数据不出企业围墙

**触发条件**：公共数据池已有成功案例→企业看到分润效果→自愿接入。不是强制，是激励。

**方式**：企业数据不离开本地服务器，只通过联邦学习/TEE/差分隐私暴露结构化特征供外部调用。每次调用按贡献值自动结算。

### 第三步：全生态开放（4-7年）

**场景**：中小企业、个人开发者、消费者自由接入

**目标**：全民众包，消费者池+生产者池双向分润。

---

## 总览

```
基础层（现在可做）→ 核心层（基础验证后）→ 扩展层（核心稳定后）→ 全态层（条件成熟后）

      公共数据沙盒              区域验证               行业联邦开放              全民众包
      可控、可审计          跨区域、多主体          有限开放、规模化          全民参与、标准化
```

---

## 第一层：基础层（公共数据沙盒验证期）

### 核心命题

在可控的封闭环境中跑通「公共数据从原始非结构化文档到结构化数据产品」的最小闭环。验证数据价值链的物理可行性。

### 实现条件

- 基础设施已就位（算力、电力、数据存储）
- 有可培训的本地劳动力
- 有至少一个公共数据源合作方（如地方档案馆、三甲医院、交通管理部门、国企）

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **基础设施** | 算力池上线、数据存储到位 | 绿色能源优先，不绑定具体地点 |
| **数据源接入** | 1-2个公共数据源方签署合作协议 | 政务档案、医疗数据、交通数据 |
| **数据结构化** | OCR/NLP基础管线部署 | 可AI辅助，人工审核 |
| **数据标注** | 本地劳动力完成初级标注任务 | 标准化的通用任务 |
| **贡献值记录** | **仅轨道A（基础贡献值）** | 工时×准确率，先不做事后修正 |
| **存证** | 核心操作上链存证（血缘+贡献值） | 可用轻量联盟链 |
| **分配** | 预分配机制（虚拟代币或人工审核后发放） | 不跑智能合约自动分润 |

### 本层不做的

- 不做市场检验修正（轨道B）——下游还没有真实AI产品产生利润
- 不做智能合约自动分润——收益流还没有形成
- 不做消费者池——数据产品还没有终端用户
- 不做税收嵌入——分配规模太小，暂按现有税制处理

### 本层产出

- 至少一个完整的数据产品闭环案例（如某档案馆的历史文档数字化后成为可查询数据集）
- 贡献值记录系统的基础数据积累（足够校准轨道A的参数）
- 标注员真实收入数据（对照基础贡献值，为下一层做基准）

### 达标验收标准

- 至少完成两类数据源的处理（如政务档案+工业图纸）
- 贡献值记录的完整性 > 98%
- 参与者对分配公平性的主观满意度 > 60%

## 第二层：核心层（区域验证期）

### 核心命题

在基础层验证通过后，引入真实的市场化收益流，启用智能合约自动分润和轨道B市场修正。从「模拟分配」切换到「真实分配」。

### 实现条件

- 基础层达标验收通过
- 有至少一个外部城市的数据源与沙盒数据链路打通
- 有一个或多个AI产品开发者愿意基于沙盒数据元件开发真实产品
- 联盟链基础设施完成部署

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **跨区域数据对接** | 1-2个外部城市的政务/企业数据源接入 | 测试跨区域隐私保护 |
| **数据元件化** | 将结构化数据封装为标准数据元件 | 标准化接口、元数据规范 |
| **数据产品开发** | 外部开发者基于数据元件开发真实AI产品 | 产品在市场中产生真实利润 |
| **贡献值计量** | **轨道A + 轨道B（市场检验修正）** | 双轨制正式运行 |
| **智能合约分润** | 利润沿数据价值链自动分配 | 合约部署在联盟链上 |
| **SPV法人治理** | 园区SPV正式运营，管理利润流和分配流 | 独立审计 |
| **数字人民币结算** | 分配款以数字人民币到账 | 参与者开立数字钱包 |
| **基础治理** | 试点社区投票确定参数初始值 | 复杂度等级映射等 |

### 本层不做的

- 不做半开放众包——加工方限于园区培训的本地劳动力和远程审核员
- 不做消费者池——终端产品利润先全部分配给生产者
- 不做历史贡献因子——先在核心机制跑通后再扩展
- 不做合成数据衰减——本阶段合成数据占比低

### 本层产出

- 智能合约自动分润在真实环境中连续运行超过6个月
- 轨道B（市场修正）的设计参数经真实数据校准
- SPV治理结构、成本核算、分润频率经过独立审计

### 达标验收标准

- 智能合约分润触发次数 > 100次，无合约执行错误
- 参与者分润到账的满意率 > 70%
- 数据产品至少产生可统计的市场收益
- 跨区域数据传输的安全审计通过

---

## 第三层：扩展层（行业联邦开放期）

### 核心命题

在核心机制稳定运行后，将数据来源从公共数据扩展为企业数据，通过隐私计算实现联邦接入。同时引入AI工具增益归算、历史贡献因子、税收三层嵌入。

### 实现条件

- 核心层稳定运行超过12个月
- 贡献值标准化在试点社区达成共识
- 监管机构确认方案符合现有法规框架
- 数字人民币智能合约接口可用

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **行业联邦节点** | 向特定行业/大型企业开放，通过隐私计算接入 | 数据不出企业围墙 |
| **分布式数据源** | 多方数据源持续接入 | 公共数据+企业联邦数据 |
| **AI工具增益归算** | 产出量加成系数正式运行 | 效率增益归操作者 |
| **历史贡献因子** | 5%-10%归出生地政府的机制上线 | 需实际居住年限条件 |
| **税收三层嵌入** | 个人所得税归工作地 / 企业税按运营区域分享 / 出生地回偿 | 税务机关监管节点接入联盟链 |
| **治理双层设计** | 社区治理层+公共治理层分治 | 投票机制进入运行 |
| **熔断机制** | 三方多签熔断部署 | 受独立审计 |

### 本层不做的

- 不做全民众包——仅限于经过培训认证的参与者和合规接入的企业
- 不做消费者池——本层仍以生产者为核心
- 不做合成数据代际衰减——合成数据占比尚未达到需要规则的程度

### 本层产出

- 跨区域、多主体的分布式数据价值网络初步形成
- 历史贡献因子运行数据——验证对出生地政府的实际激励效果
- 税收三层嵌入在税务机关审计中通过

### 达标验收标准

- 外部参与者的贡献值满意度 > 70%
- 历史贡献因子给出生地政府带来的实际回流金额有统计数据
- 至少两个出生地政府基于回流数据调整了教育/人口投入策略
- 半开放众包的质量控制体系通过独立审计

---

## 第四层：全态层（全民众包期）

### 核心命题

整个系统的最终形态。生产者池+消费者池双向分润、合成数据代际衰减、跨平台数据协议标准化。从「行业分配机制」进化为「社会级参与范式」。

### 实现条件

前三层全部达标。且：

- 贡献值量化标准已被至少一个国家级标准组织采纳
- 智能合约分润机制已在真实环境中连续运行超过12个月无重大争议
- 数据隐私保护和监管机制已通过独立合规审计
- 平台已具备处理多源异构数据的大规模并发能力

### 本层包含的模块

| 模块 | 本层要求 | 备注 |
|------|---------|------|
| **全民众包** | 全类型任务向社会开放，无需培训认证即可参与初级任务 | 质量校验层把关 |
| **消费者池** | 终端利润的10%-15%分配给消费者 | 先覆盖可验证链上消费 |
| **双向分润** | 生产者池+消费者池并行运行 | 两条独立轨道 |
| **消费值计量** | 初期用链上消费记录做代理变量 | 传播类/注意力类暂不纳入 |
| **合成数据代际衰减** | 等比衰减规则正式运行 | 合成数据占比已需要规则 |
| **跨平台数据协议** | 推动数据贡献追踪协议的行业标准 | 中长期标准化工作 |
| **开发者反垄断** | 公共数据元件强制开放条款生效 | 防止数据垄断 |
| **全面治理成熟** | 全部参数实现链上治理，消费者纳入投票体系 | |

### 本层产出

- 亿级参与者覆盖的全民数据价值生态
- 消费者分润的宏观数据（验证对消费行为的激励效果）
- 合成数据衰减规则在真实场景中的运行数据
- 跨平台数据贡献协议的标准草案

## 层级递进逻辑

```
基础层：     验证「数据能不能变成产品」
              ↓
核心层：     验证「产品利润能不能自动分润」
              ↓
扩展层：     验证「更多人和更多区域能不能参与进来」
              ↓
全态层：     验证「全社会的生产者和消费者能不能一起分享」
```

---

## 每层可以失败

失败是预期的。每层失败的结果不是退回方案本身，而是让方案产生一个明确的修订版。

| 层级 | 最可能的失败点 | 失败后的修正方向 |
|------|-------------|----------------|
| 基础层 | 贡献值记录的数据质量不足以支撑后续计算 | 重新设计「何为一个有效的贡献记录单元」 |
| 核心层 | 轨道B修正因子与实际市场价值偏差过大 | 切换工程近似方法或调整α值 |
| 扩展层 | 历史贡献因子未产生预期的出生地激励 | 调整比例或生效条件 |
| 全态层 | 消费者分润被套利 | 收紧消费值计量口径 |

每层失败都有明确的诊断方向和修正空间。方案不承诺一步成功，承诺的是每一次迭代都比上一次接近正确。

## 与四阶段演进路径的对应关系

本分层设计对应方案已有演进路径，但每一层的模块划分更精细：

| 演进阶段 | 对应层级 | 核心交付 | 数据来源 |
|---------|---------|---------|---------|
| 阶段一：公共数据沙盒 | 基础层 | 数据价值链的物理可行性 | 政府公开数据 + 国企行业数据 |
| 阶段二：区域验证 | 核心层 | 智能合约分润的工程可行性 | 公共数据 + 少量外部数据 |
| 阶段三：行业联邦开放 | 扩展层 | 多主体、跨行业、隐私保护的制度可行性 | 公共数据 + 企业联邦数据 |
| 阶段四：全民众包 | 全态层 | 全民参与的社会可行性 | 全社会数据 |
