# 贡献值计量详解

> 双轨制：输入端劳动价值论 + 输出端市场价值论  
> 双因子：直接贡献（当下劳动）+ 历史贡献（社会投资回偿）

---

## 一、为什么需要双轨

单纯的「按工时计件」（劳动价值论）无法区分高质量产出和低质量产出。一个标注了100张猫图和10张罕见病病理切片的人，劳动投入相近，但AI时代的价值产出差几个数量级。

单纯的「事后Shapley值分配」（市场价值论）无法保障基础收入。如果标注员干了一个月发现自己的数据后来都没产生收益，等于白干。

**双轨制**：先按劳动给基础贡献值（能活），再按市场收益做事后修正（能富）。

---

## 二、轨道A：基础贡献值

### 公式

```
贡献值_A = T x A x C x S
```

| 符号 | 含义 | 计量 | 更新频率 |
|------|------|------|---------|
| T | 工时 | 系统自动记录链上时间戳 | 实时 |
| A | 准确率因子 | 质量校验层抽样验证，交叉验证+专家抽检 | 每日 |
| C | 复杂度等级 | 预定义任务分级表L1-L5，社区投票确定映射 | 试点校准后固化 |
| S | 稀缺性加权 | 根据该类型数据在全局数据池中的总存量动态计算，存量越大稀缺性越低 | 每月 |

### 稀缺性参数详解

**核心原则**：不判断两条数据是否"重复"，而是统计该类型数据在全局数据池中的总存量。存量越大 → 稀缺性越低 → 单条贡献值越小。

**为什么用"类型总量"而非"逐条去重"**：
逐条判断"张三的感冒数据和李四的感冒数据是不是重复的"在工程上不可行——两份手写病历的潦草程度不同、措辞不同、诊断细节不同，但它们在模型训练中的边际价值差异极小。用类型总量替代逐条比较，简洁、可计算、避免了无休止的仲裁争议。

**动态衰减模型**：

```
稀缺性 S = 1 / (1 + k × N_type)
```

其中 N_type 为该类型数据在全局池中的累计条目数，k 为衰减速率常数（初始 0.01，社区治理调整）。

| 感冒症状数据（N=10000） | 罕见病数据（N=3） |
|---|---|
| S ≈ 1/(1+100) = 0.01 | S ≈ 1/(1+0.03) ≈ 0.97 |
| 第10001条感冒数据贡献值极低 | 第4条罕见病数据贡献值极高 |

**稀有度触发阈值**：当 N_type < 100 时，系统自动将稀缺性锁定在 ≥0.5，确保稀有样本提供者不会被系统边缘化。

**稀缺性的双重含义**：S 不仅反映"市场上这种数据少"，也间接反映**获取这种数据的真实成本**——罕见病样本稀少是因为痛苦无法量产，极端环境监测数据稀少是因为采集者承担了真实风险，濒危物种数据稀少是因为种群本身在消亡。S 参数是系统对这些隐性代价的经济定价。

### 复杂度等级（L1-L5）

| 等级 | 典型任务 | 权重 |
|------|---------|------|
| L1 | 通用文本分类、简单图像打标 | 1.0 |
| L2 | 专业文本标注、多标签分类 | 1.5 |
| L3 | 医疗影像分区、法律文书分类 | 2.5 |
| L4 | 罕见病标注、古籍文献识别 | 4.0 |
| L5 | 边缘案例鉴定、标注规则制定 | 6.0 |

### 准确率因子

| 准确率 | A因子 |
|--------|-------|
| >= 99.5% | 2.0 |
| >= 99.0% | 1.5 |
| >= 97.0% | 1.0 |
| >= 95.0% | 0.7 |
| < 95.0% | 0.3（触发复训） |

## 三、轨道B：市场检验修正

### 触发条件

下游数据产品产生市场化收益时触发。不产生收益则不触发修正。

### 算法框架

采用**Shapley值**或其工程近似：

对于数据产品产生收益R，上游有n个贡献节点。节点i的修正贡献值为：

```
修正贡献值_i = 初始贡献值_i x (1 + α x Shapley_i / ΣShapley)
```

其中α为修正强度系数（初始可取0.5，试点校准）。

### 工程近似方案

精确Shapley值的计算复杂度为O(2^n)，在大规模场景下不可行。本方案采用以下工程近似之一：

1. **截断蒙特卡洛采样（TMC-Shapley）**：Ghorbani & Zou (2019) 的方法，随机采样排列并计算边际贡献，在实践中O(n log n)可达到合理精度
2. **Integrated Gradients近似**：利用梯度信息估计每个数据点对模型输出的边际影响
3. **Leave-One-Out近似**（初期可用）：逐节点移除后观测性能变化

### 修正反馈回路

```
市场收益 → 反向传播 → 贡献值修正 → 分配调整 → 激励变化 → 质量提升 → 更高收益
```

## 四、轨道C：AI工具增益归算

### 原则

AI无法律人格，不参与分配。效率增益归操作者。

### 具体规则

- 标注员用AI辅助 → 效率提升10倍 → 10倍的产出贡献值归标注员
- 算法工程师用AI调参 → 增益归工程师
- 增益体现为产出量加成系数，不为AI单独开设分配科目

### 类比

用挖掘机挖土效率比铲子高，功劳归挖掘机司机，不归挖掘机制造商。制造商的价值在设备出售时实现，不在每次使用中重复分配。

### 系数设计

```
产出量加成系数 = 1 + β x (实际产出 / 标准人效基准 - 1)
```

其中β ∈ [0, 1]，控制增益分配偏向操作者还是保留在平台（初始可取β=1.0，即全部归操作者）。

## 五、轨道D：合成数据代际衰减

### 问题

人类标注一小批 → AI学习 → AI生成99%的训练数据。初始标注者该分多少？

### 数学模型

```
第N代贡献追溯权重 W_N = W_0 x r^N
```

其中：W_0 = 1.0（基准），r = 0.5（衰减率）

| 代际 | 权重 | 累计 |
|------|------|------|
| 0 | 1.000 | 1.000 |
| 1 | 0.500 | 1.500 |
| 2 | 0.250 | 1.750 |
| 3 | 0.125 | 1.875 |
| ∞ | 0.000 | 2.000 |

### 数学性质

等比级数严格收敛：Σ(0.5^N) = 2.0，N→∞

无限代际总追溯权重有限，不会出现权重爆炸。衰减规则固化在智能合约中，无需人工判断。

### 进阶

未来可引入**Influence Function**（Koh & Liang, 2017）精确计算每个初始种子数据对最终合成数据的边际影响，替代一刀切衰减系数。当前用等比衰减作为可工程化的初始近似。

## 六、轨道E：历史贡献因子

### 问题

一个人的劳动能力不是凭空产生的。出生地的教育、医疗、治安等社会投入，把自然人变成了合格的数据劳动者。如果这套投入在劳动者产生价值后没有任何回偿，地方政府就没有动力进行长期人力资本投资。

### 数学模型

```
劳动者总贡献值 = 直接贡献值 × (1 + h)
```

其中 h 为历史贡献因子，取值范围 [0.05, 0.10]。

| 劳动者 | 直接贡献值 | h=0.08 时的历史贡献 | 历史贡献流向 |
|--------|-----------|-------------------|-------------|
| 标注员A | 10,000 | 800 | A的出生地政府 |
| 审核员B | 25,000 | 2,000 | B的出生地政府 |
| 算法工程师C | 50,000 | 4,000 | C的出生地政府 |

### 设计约束

| 参数 | 取值 | 理由 |
|------|------|------|
| h 上限 | 10% | 不超过总贡献值的十分之一，保持按劳分配主体 |
| h 下限 | 5% | 不低于感知阈值，确保激励可量化 |
| 生效条件 | 出生地居住满10年或完成义务教育 | 防止「只落户不住人」套利 |
| 归属 | 全部归出生地政府 | 劳动者本人已获得直接贡献的90%+ |

### 政策含义

历史贡献因子将生育从「地方短期财政负担」重新定义为「可计算回报的长期社会投资」。一个孩子 = 未来每年给出生地带来持续税收回流。地方政府第一次有了制度性理由去鼓励生育和加大基础教育投入——不是靠行政命令，是靠算法和合约。

## 七、轨道F：平台与资本贡献（独立处理）

### 为什么不在公式里加平台维度

轨道A-E覆盖的是**劳动贡献**——数据提供者的稀缺样本、标注员的工时和准确率、工程师的技术产出。它们可以统一在一个乘法公式中，因为它们共享"投入越多→贡献越大"的线性逻辑。

平台的贡献不属于这一维度。平台搭建基础设施、撮合供需、管控质量、封装产品——这些是**资本和组织贡献**，逻辑不同于劳动投入。强行将平台塞入贡献值公式（例如加一个"平台效能系数"），会破坏公式的简洁性和可解释性。

### 独立处理方式

| 平台贡献 | 处理方式 | 位置 |
|---------|---------|------|
| 基础设施搭建（算力、存储、网络） | 从终端利润中优先扣除运营成本 | L4 收益分配子系统 |
| 供需撮合、质量管控 | 平台服务费（固定比例，如3%-5%） | L4 SPV运营成本 |
| 数据产品封装与交易对接 | 产品化增值部分由SPV独立核算 | L4 成本核算模块 |

### 设计原则

**劳动贡献进公式，资本贡献进成本表。** 贡献值公式回答"谁劳动了多少"，成本扣除和服务费回答"谁投入了多少资源和组织能力"。两者分开处理，各自透明，互不污染。

### 未来演进

当平台达到规模效应后，固定比例的服务费可能显得过高。此时可通过链上治理提案调整费率，或将超额服务费转入L5的稀缺数据公共保障基金，避免平台形成"抽成依赖症"。

## 八、治理接口

### 参数治理范围

| 参数 | 初始取值 | 治理方式 |
|------|---------|---------|
| 复杂度等级映射 | 试点社区讨论 | 链上提案+多签表决 |
| 准确率阈值 | 基准97% | 行业标准对齐 |
| 修正强度α | 0.5 | 试点数据校准 |
| 衰减率r | 0.5 | 合约写死（升级需分叉） |
| 增益系数β | 1.0 | 社区治理 |
| 历史贡献因子h | 0.08 | 综合试点政府数据校准 |

### 参数冻结期

任何参数修改后有最短6个月的冻结期，防止频繁修改破坏参与者预期。
